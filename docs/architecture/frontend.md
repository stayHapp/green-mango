# 前端架构

本文档记录三端前端当前结构与逐步联调边界。

## 页面结构

当前页面按三个客户端组织：

- 管理员端：统一登录、会议列表和会议级工作台。会议级工作台使用 `AdminWorkspaceLayout.vue` 提供固定侧边导航、顶部会议上下文和统一退出入口；该界面按 PC 管理工作台设计，最小展示宽度为 1180px，窄窗口通过横向滚动保持完整桌面信息密度，不提供手机端堆叠版；详情区块通过 `?tab=overview|edit|guests|import|fields|assistant|staff|checkins` 保持可直达状态。
- 工作人员端：会议专属登录、会议授权校验和签到工作台；旧负责会议列表仅作为兼容入口保留。
- 嘉宾端：会议专属入口身份核验、当前会议首页、个人资料、签到状态和会议服务。

## 组件规划

可逐步抽取以下组件：

- 会议基础信息表单
- 报名字段配置表格
- 报名字段编辑器
- 动态报名表渲染组件
- 报名记录表格
- 字段值展示组件

## API 请求封装

`frontend/src/api/` 已提供：

- `client.ts`：从 `VITE_API_BASE_URL` 读取基础地址，默认使用 `http://127.0.0.1:8000/api`。
- 管理员端会议入口链接优先使用 `VITE_PUBLIC_APP_URL` 作为公开前端地址；本地联调配置本机局域网 IP，部署时配置正式域名，避免二维码包含其他设备无法访问的 `localhost`。
- `authStorage.ts`：按管理员、工作人员、嘉宾分别保存用户展示数据、Bearer token 和过期时间。
- `sessions.ts`：三端登录、公开会议入口、嘉宾个人资料和统一退出请求。
- `adminMeetings.ts`：管理员会议列表、创建、详情和修改。
- `adminGuests.ts`：管理员嘉宾列表、新增、完整资料、动态字段读取和二维码批量生成。
- `adminExcel.ts`：管理员嘉宾导入模板、XLSX 名单上传和全量签到表下载。
- `adminStaff.ts`：管理员查询、创建、修改工作人员，以及解除会议授权。
- `adminCheckIns.ts`：管理员读取和维护签到场次、签到规则、当前场次统计、签到明细和相邻场次差异。
- `meetingAssistant.ts`：管理员与嘉宾读取五项会议服务正文、发布状态和访问级别。
- `meetingMaterials.ts`：管理员维护会议资料条目和附件，嘉宾或公开访客按权限读取资料和下载附件。
- `meetingWeather.ts`：公开和登录场景读取会议天气数据。
- `staffCheckIns.ts`：工作人员读取负责会议、当前有效签到场次、搜索嘉宾、查询签到记录并执行扫码或人工签到。
- `guestMeetings.ts`：嘉宾读取本人当前会议详情、会议服务入口、签到二维码和签到状态。

授权业务 API 使用 `authorizationConfig(role)` 注入相应客户端 token；FastAPI 的 `detail` 和网络错误由统一函数转换为页面中文提示。

## 路由规划

当前主要路由：

- `/login`
- `/admin/meetings`
- `/admin/meetings/:id`
- `/meetings/:id`
- `/meetings/:id/staff/login`
- `/guest/login?meetingId=:id`
- `/guest/meetings`
- `/guest/meetings/:id`
- `/staff/meetings`
- `/staff/meetings/:id/check-in`

管理员与工作人员共用 `/login`，嘉宾必须从独立会议入口进入。

工作人员的主入口位于 `/meetings/:id` 公开会议首页底部，并进入 `/meetings/:id/staff/login`。登录成功后前端调用工作人员负责会议接口校验当前会议授权，授权成功直接进入 `/staff/meetings/:id/check-in`，不再要求工作人员二次选择会议。`/staff/meetings` 和统一登录中的工作人员页签作为历史兼容入口保留。

嘉宾身份属于会议级记录。`/guest/login?meetingId=:id` 与当前会议首页复用 `GuestMeetingSummary.vue` 展示同一会议概要，并使用报名时填写的姓名和手机号完成身份核验；正式界面不提供示例身份填充，也不重复展示手机号用途说明。空字段使用“报名时填写”的表单项错误并聚焦第一个错误输入框，身份不匹配等服务端错误显示在提交按钮之前。核验成功后进入 `/guest/meetings/:id` 当前会议首页。`/guest/meetings` 仅作为历史兼容路由，已登录时直接跳转到会话所属会议，不展示跨会议列表。

## 状态管理规划

Pinia 当前只保存三端用户和访问会话。登录成功后同步到 localStorage，页面刷新可恢复未过期会话；已过期或结构无效的存储会被自动删除。

退出登录先调用后端撤销 token，再清除 Pinia 与 localStorage。即使后端暂时不可用，本地状态也会清理；嘉宾返回原会议登录入口并清空姓名、手机号。

管理员会议列表、创建、详情和修改已通过 `frontend/src/api/adminMeetings.ts` 使用真实 API。管理员会议详情中的数据总览直接组合真实嘉宾、工作人员和签到统计数据；嘉宾列表、新增、查看、编辑、软删除、完整资料和动态字段已通过 `frontend/src/api/adminGuests.ts` 使用真实 API，并在页面内处理加载与错误状态。新增与编辑弹窗按当前启用的动态字段生成输入项，详情弹窗同时展示这些字段；动态必填字段在提交前由前端提示并由后端再次校验。正式嘉宾的二维码 token 在形成嘉宾记录时由后端自动签发，嘉宾管理页不提供重复的批量生成入口。

管理员会议工作台采用单层内容容器：页面区块本身不再增加卡片外框，筛选与表格通过留白和细分隔线建立层级。会议信息页统一使用四列网格：名称占两列，地点和发布控制各占一列；开始、结束时间各占一列，导航位置占两列；说明和底部操作栏独占整行。发布控制只修改表单草稿，仍由统一保存操作提交。嘉宾 Excel 导入由嘉宾管理页弹窗承载，不再使用独立的 `import` 页签状态。

嘉宾字段页新增扩展字段时只要求管理员填写可见的字段名称；前端自动生成以 `custom_` 开头的稳定唯一 key，并在保存后沿用该 key。字段标识属于系统内部关联信息，不要求管理员手工填写，也不在界面中暴露。

嘉宾端公开入口、登录、报名、会议首页和会议服务详情统一使用与工作人员端、管理后台一致的浅绿色页面画布 `#f6f8f7`；内容面板继续使用白色，保持页面层级和信息可读性。

管理员端 Excel、工作人员维护和签到统计已接入真实 API。工作人员端负责会议、当前签到场次、嘉宾搜索、扫码签到、人工签到和签到记录也已完成真实联调；移动工作台使用扫码签到、手动签到和签到记录三个底部导航状态，手动签到采用“搜索—选择—核对—确认”流程。扫码页点击扫码区域开启摄像头，开启后保持连续扫码，直到工作人员点击画面关闭按钮或离开扫码页。工作人员端按 `visible_fields` 控制单位、身份、座位号等字段展示，后台未启用的字段不出现在搜索提示、列表摘要和核对卡片中。重复扫码或重复人工签到时，页面展示后端返回的已有签到时间、签到方式和执行人员。页面按资源维护局部加载与错误状态，不把业务数据放入全局状态。

会议服务已经接入真实后端 API。管理员可按会议读取并编辑五项功能的通用正文、未发布提醒、发布状态和访问级别；访问级别支持“公开可见”和“仅登录嘉宾可见”，历史配置默认仅登录可见。会议日程由 `AdminAgendaEditor.vue` 在前端将既有正文解析为日期、时段和环节结构，单条环节收敛为时间段、环节、内容和地点。`AgendaRichTextEditor.vue` 使用原生可编辑区域提供换行、加粗和缩进，`agendaRichText.ts` 负责白名单清洗以及 `rich:` 单行编码与解码；保存时仍序列化回通用正文，因此不要求修改现有 API 或数据库。会议资料由 `AdminMeetingMaterialsEditor.vue` 维护多条资料标题、正文、排序和附件，`MeetingMaterialRichTextEditor.vue` 使用受限富文本编辑并在保存、展示前清洗。历史三字段和四字段正文会将主题、嘉宾说明合并到内容区。公开会议首页点击服务时先调用公开接口：公开服务进入带 `access=public` 查询参数的复用详情页，受限服务提示完成当前会议身份核验。已登录嘉宾继续使用嘉宾接口，不受公开访问级别限制。天气详情在公开模式与登录模式分别调用对应天气接口。固定入口标题与说明仍由前端维护；未发布响应不包含正文、资料条目、附件或联系人草稿。

嘉宾二维码组件通过真实二维码接口读取 token、有效期和签到状态。未签到时展示可扫描二维码；当前会议首页存在签到记录时收起二维码，以成功状态和本地签到时间为主。嘉宾首页在未签到且页面可见时每 3 秒轮询一次签到状态，工作人员扫码后可自动切换为已签到；页面隐藏、退出登录或已签到后停止轮询。刷新页面或重新登录后可恢复服务端状态。

嘉宾当前会议首页已接入真实 API。页面复用登录时由个人资料接口返回的固定资料，并组合真实二维码与会议服务入口，形成会议级身份核验、当前会议详情和签到状态的完整访问链路。首页以紧凑会议概要和参会凭证为主；身份与签到组合展示，单位、职位和脱敏电话使用明确标签，空字段不占位。顶部左侧为会议服务菜单，右侧使用图标和“退出”文字提供退出操作。未签到时不重复展示状态文字，二维码和操作说明居中呈现；会议服务入口通过 Element Plus Drawer（抽屉）从左侧展示五项服务并复用既有详情路由。五项服务详情页统一使用墨绿色内容主题，以及“左侧返回、黑色服务标题居中”的标题栏，正文区域不再重复渲染标题。日程正文在前端解析为日期切换、上午或下午分组和紧凑时间轴；日期切换和时间列使用紧凑高度，顶部摘要仅显示当日时间范围，不显示环节数量。日程内容富文本在渲染前再次执行白名单清洗；无法识别的行继续作为普通环节安全展示。

三端业务页面已不再依赖前端 Mock API，正式发布包中不保留前端 Mock 数据目录。管理员、嘉宾和工作人员页面均通过真实后端接口读取业务数据。

管理员会议编辑页通过后端高德代理搜索并选择导航地点，页面只保存地点名称、地址和坐标，不接触高德服务端 Key。嘉宾路线页使用高德 URI 打开手机导航，并将会议助手“路线指引”正文作为到场说明展示。天气和导航共用管理员确认坐标，避免文字地点匹配偏差。

管理员会议详情的“签到管理”已接入真实场次和统计接口。该入口包含场次列表、按日期生成、新增场次、场次编辑删除、默认场次手动调整、当前场次签到记录，以及当前场次相对前一场次的新增签到和减少签到名单。签到明细固定在统计区域内通过滚动或分页展示人员列表，放大入口在弹窗中展示更完整信息。签到统计作为独立资源加载，失败时只在签到页签展示错误，不影响会议、嘉宾、工作人员和会议助手等其他资料。

签到时间由服务端统一按 UTC 语义返回。工作人员 API 适配层兼容 SQLite 或旧服务返回的无时区 UTC 文本：仅在响应没有 `Z` 或时区偏移时补充 UTC 标识，再由浏览器统一转换为本地时间，避免跨端出现 8 小时时差。
