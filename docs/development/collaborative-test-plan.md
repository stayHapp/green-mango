> 同事直接执行时，请使用配套的 [同事测试任务清单](./colleague-test-checklist.md)。本文件供测试负责人准备数据、分配任务、汇总结果和安排收尾使用。

> 同事直接执行时，请使用配套的 [同事测试任务清单](./colleague-test-checklist.md)。本文件供测试负责人准备数据、分配任务、汇总结果和安排收尾使用。

## 1. 测试目的

邀请公司同事从真实使用者角度验证系统的核心流程、页面可用性、权限控制和异常提示，尽早发现影响会议管理、嘉宾报名、现场签到和会议服务的问题。

本轮测试重点不是验证代码实现，而是确认：

- 用户能否按照页面提示完成操作。
- 不同角色是否只能访问自己有权限的数据和功能。
- 会议管理员、工作人员和嘉宾之间的数据是否能够正确衔接。
- 手机端和电脑端的主要页面是否能够正常使用。
- 错误操作、重复操作和刷新页面后，系统是否给出清晰且合理的结果。

## 3. 测试角色分工

### 3.1 测试负责人

负责：

- 创建测试会议、测试账号和测试嘉宾数据。
- 将测试地址、账号和测试任务分配给同事。
- 汇总问题并判断优先级。
- 测试结束后清理测试数据。

### 3.2 管理员测试人员

负责验证：

- 管理员登录和退出。
- 会议创建、编辑和发布。
- 嘉宾信息管理和 Excel 导入。
- 报名字段配置。
- 工作人员账号和会议授权。
- 会议服务、会议资料和签到场次配置。

### 3.3 工作人员测试人员

负责验证：

- 工作人员登录和会议授权。
- 搜索嘉宾。
- 扫码签到。
- 手动签到。
- 重复签到和签到记录。
- 手机端现场操作体验。

### 3.4 嘉宾测试人员

负责验证：

- 公开会议首页。
- 自主报名。
- 嘉宾身份核验。
- 会议首页和签到二维码。
- 会议服务、会议资料和天气等入口。
- 退出、刷新和重新登录后的状态恢复。

## 4. 测试前准备

测试负责人提前准备以下数据：

1. 一个已发布的测试会议。
2. 一个未发布的测试会议，用于验证公开访问限制。
3. 至少 5 位测试嘉宾：
   - 资料完整的嘉宾 1 位。
   - 缺少单位、职位或座位号等可选资料的嘉宾 1 位。
   - 存在自定义字段的嘉宾 1 位。
   - 尚未签到的嘉宾 1 位。
   - 已签到的嘉宾 1 位。
4. 一个已授权当前会议的工作人员账号。
5. 一个未授权当前会议的工作人员账号。
6. 一份正常的 Excel 嘉宾名单。
7. 一份包含缺失必填列、重复手机号或格式错误数据的 Excel 文件。
8. 会议日程、会议资料和至少一项会议服务内容。
9. 一个公开可见的会议服务和一个仅登录嘉宾可见的会议服务。
10. 至少两个签到场次，例如“上午签到”和“下午签到”。

## 5. 测试执行规则

每个测试人员执行分配到的用例，并记录以下内容：

- 用例编号。
- 执行结果：通过 / 失败 / 阻塞。
- 实际表现。
- 浏览器、设备和操作系统。
- 截图或录屏。
- 发生问题的时间。
- 如果是失败，是否可以稳定复现。

遇到问题时不要反复刷新或修改数据掩盖现象。先记录页面状态，再将问题反馈给测试负责人。

## 7. 跨角色联调流程

### 流程一：报名到签到

1. 嘉宾打开公开会议首页。
2. 嘉宾提交自主报名。
3. 管理员确认报名记录并完善或审核嘉宾资料。
4. 嘉宾使用姓名和手机号完成身份核验。
5. 嘉宾打开个人二维码页面。
6. 工作人员使用二维码完成签到。
7. 嘉宾确认首页自动更新为已签到状态。
8. 管理员查看对应签到场次的统计和明细。

预期结果：报名、嘉宾资料、二维码、签到记录和统计数据能够串联起来，且使用的是同一位测试嘉宾。

### 流程二：会议服务权限

1. 管理员创建一个公开服务和一个仅登录嘉宾可见的服务。
2. 未登录访客打开公开服务，应能正常查看。
3. 未登录访客打开受限服务，应看到登录提示。
4. 嘉宾完成身份核验后重新打开受限服务，应能查看正文。
5. 管理员取消服务发布后，访客和嘉宾均不应看到该服务正文。

### 流程三：工作人员授权

1. 管理员授权工作人员负责测试会议。
2. 工作人员登录并完成一次签到。
3. 管理员解除该工作人员授权。
4. 工作人员退出后重新登录。
5. 验证工作人员不能继续进入或操作该会议。

## 8. 兼容性测试

至少覆盖以下组合：

| 类型 | 建议组合 |
| --- | --- |
| 桌面浏览器 | macOS Chrome、macOS Safari、Windows Chrome 或 Edge |
| 手机浏览器 | iPhone Safari、Android Chrome |
| 屏幕尺寸 | 电脑宽屏、普通笔记本、手机竖屏 |
| 网络情况 | 正常 Wi-Fi、手机网络、短暂断网后恢复 |

重点观察：

- 页面是否出现横向滚动或内容被遮挡。
- 弹窗、抽屉和表格是否能够正常关闭和滚动。
- 摄像头权限被拒绝时是否有明确提示。
- 页面刷新后是否丢失登录状态或当前会议上下文。
- 服务器接口异常时是否出现空白页或无意义报错。

## 9. 缺陷反馈模板

请每个问题单独反馈，不要把多个问题混在一条消息中。

```text

【测试环境】浏览器、设备、操作系统
【前置数据】会议名称、测试嘉宾或签到场次

1.

【预期结果】
【实际结果】
【复现次数】例如 3/3
【附件】截图或录屏
```

### 优先级定义

- **阻塞**：无法登录、无法进入核心页面、无法签到，导致测试无法继续。
- **严重**：核心数据错误、权限越权、签到记录丢失或错误归属。
- **一般**：功能可以继续使用，但提示、布局或部分流程不符合预期。
- **建议**：不影响当前使用的文案、样式或交互优化建议。

## 11. 验收标准

满足以下条件后，本轮测试可以结束：

- 管理员、工作人员和嘉宾三类角色均完成核心流程测试。
- 报名到签到的跨角色流程能够完整跑通。
- 正常登录、退出、刷新和重新进入流程均通过。
- 工作人员能够完成扫码签到和手动签到。
- 重复签到、无效二维码和未授权账号均被正确拦截。
- 会议服务的公开和登录权限符合配置。
- 手机端嘉宾流程和工作人员签到流程没有阻塞性布局问题。
- 没有未解决的阻塞问题或严重数据问题。
- 所有失败用例都有明确处理结论：修复、延期或确认不影响发布。

## 12. 测试结束后的数据清理

测试完成后由测试负责人：

1. 删除或停用测试嘉宾。
2. 删除或取消发布测试会议。
3. 取消测试工作人员的会议授权。
4. 清理测试上传的附件和测试文件。
5. 确认测试数据中没有真实姓名、手机号或其他个人敏感信息。
6. 保存最终测试结果和未解决问题清单。
