# 0060 签到管理页面优化

## 任务名称

优化后台签到管理页面。

## 背景

0059 已实现签到场次和后台签到管理，但页面信息密度和视觉组织较弱。用户确认新的样图方向：三种签到模式对应的签到场次都使用同一个前端模块展示，并且所有模式都允许手动调整默认场次。

## 用户确认状态

用户已确认样图方向，可以开始实现。

## 目标

1. 将“签到管理”优化为模式选择、统一场次列表、默认场次摘要、签到记录查看和场次对比的组合界面。
2. 单场、按日期、自定义场次共用同一个场次列表模块展示。
3. 支持按会议起止日期生成日期场次。
4. 支持在场次列表中手动设置默认场次。
5. 在页面底部展示工作人员端当前签到场次预览。

## 不在本次范围内的内容

1. 不新增后端签到模式持久化字段。
2. 不修改工作人员端选择场次能力。
3. 不改变 0059 已有数据库结构。

## 涉及文件

- `frontend/src/views/admin/AdminMeetingDetailView.vue`
- `frontend/src/styles.css`
- `docs/exec-plans/completed/0060-check-in-management-ui-optimization.md`

## 分步计划

1. 重构签到管理页签模板。
2. 增加签到模式、场次搜索、按日期生成和设为默认的页面逻辑。
3. 增加专用样式，贴近已确认样图。
4. 运行前端构建、后端测试和差异检查。

## 验收标准

1. 签到管理入口视觉结构接近确认样图。
2. 三种模式下都展示同一个场次表。
3. 日期模式可以根据会议日期创建日期场次。
4. 任意场次可手动设为默认场次并刷新统计。
5. 页面能展示工作人员端当前场次预览。

## 验证方式

1. `npm run build`
2. `.venv/bin/python -m pytest`
3. `git diff --check`

## 风险与注意事项

1. 本次模式选择暂为前端状态，不跨刷新持久化。
2. 日期场次通过现有创建场次 API 逐条创建，已存在同名场次时跳过。

## 完成记录

1. 已将后台“签到管理”页签优化为模式选择、统一场次列表、当前默认场次摘要、新增/编辑场次、签到记录查看、场次对比和工作人员端预览的组合界面。
2. 单场签到、按日期签到、自定义场次共用同一个场次列表展示模块，并支持页面内手动切换模式说明。
3. 已支持按会议开始和结束日期生成“第一天签到”“第二天签到”等日期场次，生成时跳过已存在的同名场次。
4. 已保留并强化手动调整默认场次能力，默认场次变更后会刷新场次和记录统计。
5. 已完成前端构建、后端测试、代码差异检查和浏览器渲染验收。
