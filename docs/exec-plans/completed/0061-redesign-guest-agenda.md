# 会议日程展示与结构化编辑重设计执行计划

## 任务名称

重设计嘉宾端会议日程详情页，并为管理后台提供结构化日程编辑器。

## 背景

当前嘉宾端已经把管理员维护的纯文本日程解析为日期标题和日程卡片，但每个环节使用独立大卡片，时间列宽、卡片高度和重复边框占用较多移动端空间。多日会议缺少便捷的日期切换，同一天的上午、下午等内容分段也不明显，嘉宾难以快速浏览当天安排。

本次任务以 CSSAT 第二届学术研讨会的多日、分时段日程为代表场景，在不新增后端结构化日程表的前提下，优化现有嘉宾端日程页面，并将后台的整块正文输入改为按日期、时段和环节组织的结构化编辑方式。

## 用户确认状态

用户已明确选择方案 1：后台使用前端结构化编辑器，保存时序列化回现有正文，不调整数据库和 API。嘉宾端不显示环节数量，页面标题使用黑色或主题绿色，日期字号进一步缩小。

## 目标

- 将日程从“大卡片堆叠”改为适合移动端快速扫描的日期切换和紧凑时间轴。
- 支持识别包含星期的日期行，以及上午、下午等时段分组行。
- 同一天内清晰展示开始时间、结束时间、环节名称、讲者和地点。
- 管理员按日期、时段和环节分字段编辑，不再直接输入整块日程正文。
- 嘉宾端标题使用主题绿色，日期数字收小，摘要不显示环节数量。
- 保留现有纯文本日程配置和解析失败安全展示能力，不修改后端 API。
- 在常见桌面窄栏和 390px、375px 移动端宽度下保持可读、无横向溢出。

## 不在本次范围内的内容

- 不新增结构化日程数据库表或 API。
- 不增加个人收藏、提醒、冲突检测和“我的日程”。
- 不自动导入或修改生产环境中的会议日程正文。
- 不调整天气、路线、会议资料和联系会务页面的业务逻辑。

## 技术决策与待确认项

- 保持 Vue 3、TypeScript 和现有 Element Plus 技术栈。
- 日程正文继续按行解析；扩展日期、时段和环节三种显示语义。
- 日期使用页面内切换按钮，仅影响当前前端展示，不改变路由和服务端数据。
- 默认选择与当前日期匹配的会议日；无匹配时选择第一个日期分组。
- 视觉方案以 `docs/design/guest-agenda-redesign-concept.png` 为参考，使用暖白页面、墨绿色层级、轻边框和开放式时间轴。
- 当前无需要用户进一步确认的技术项。

## 分步计划

1. 梳理现有纯文本解析规则和移动端布局问题。
2. 生成并保存符合现有嘉宾端风格的日程页面概念图。
3. 扩展日程展示模型，支持日期切换、时段分组、时间拆分和摘要。
4. 实现后台结构化编辑器，并将编辑结果序列化回现有正文。
5. 将嘉宾端大卡片样式重构为紧凑时间轴列表并补充可访问状态。
6. 同步更新会议服务、嘉宾端产品规范与前端架构说明。
7. 执行 TypeScript 构建，并在浏览器中验证后台编辑交互、嘉宾端移动响应式和日期切换。

## 验收标准

- 多日正文显示日期切换器，切换后只显示对应日期内容。
- 日期行支持 `8月18日（周二）` 等常见格式。
- `上午｜主题`、`下午｜主题` 可显示为独立分段标题。
- 日程条目以紧凑时间轴呈现，开始和结束时间清楚，讲者和地点不混淆。
- 缺少日期分组的历史正文仍能显示全部日程，不丢失内容。
- 后台可新增日期、时段和环节，现有正文打开后不会产生额外空白环节。
- 保存仍调用现有会议服务配置接口，不需要数据库迁移。
- 嘉宾端标题为主题绿色、日期字号不超过 24px，摘要不出现环节数量。
- 375px 和 390px 宽度下无横向溢出、文字遮挡或无法操作的控件。
- `npm run build` 通过，浏览器无相关警告或错误。

## 验证方式

- 在 `frontend/` 执行 `npm run build`。
- 启动本地前端与可用后端，打开嘉宾端会议日程详情页。
- 使用浏览器分别检查桌面窄栏、390px 和 375px 视口。
- 验证页面标题、非空内容、无框架错误覆盖层、控制台健康和日期切换状态。
- 对比概念图与最终浏览器截图，检查结构、层级、配色、间距和响应式。

## 风险与注意事项

- 现有日程为自由文本，无法保证所有历史格式都可被完全结构化；无法识别的行必须继续安全展示。
- 当前工作区包含签到场次管理相关的未提交修改，本次不得覆盖或回退这些修改。
- 概念图只作为视觉规格，最终界面文字和控件必须使用原生 Vue 与 CSS 实现。
