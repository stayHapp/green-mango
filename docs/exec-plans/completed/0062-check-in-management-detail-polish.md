# 0062 签到管理细节优化

## 任务名称

优化后台签到管理页面的信息层级与操作表达。

## 背景

0060 已完成签到管理页面重构，但实际渲染后仍存在首屏默认场次不够突出、默认状态表达重复、表单常驻导致页面过长、日期场次生成状态不清晰、场次对比说明不够直观等问题。

用户确认继续优化 1–5 项，并提出两处调整：

1. 去掉“允许手动调整默认场次”的按钮开关。
2. 场次列表中的默认状态只保留左侧圆点，并修复圆点渲染变形问题。

## 合理性判断

1. 去掉手动调整开关合理。三种签到模式都允许手动调整默认场次时，额外开关会造成不必要的业务分支和误操作风险。
2. 默认状态只保留左侧圆点合理。当前页面同时使用圆点、标签和操作按钮表达默认状态，信息重复；统一为左侧圆点更清晰。

## 目标

1. 在首屏增加“工作人员端当前签到场次”摘要。
2. 删除“允许手动调整默认场次”开关。
3. 默认状态仅通过左侧圆点表达，并修复圆点视觉变形。
4. 将新增/编辑签到场次从常驻表单改为弹窗，缩短主页面。
5. 日期场次生成按钮根据当前会议日期场次状态显示“生成/补齐/已生成”。
6. 场次对比区域明确展示当前场次、对比场次、新增和减少名单。

## 不在本次范围内的内容

1. 不新增后端签到模式持久化字段。
2. 不修改数据库结构。
3. 不改变工作人员端实际签到接口逻辑。

## 涉及文件

- `frontend/src/views/admin/AdminMeetingDetailView.vue`
- `frontend/src/styles.css`
- `docs/exec-plans/completed/0062-check-in-management-detail-polish.md`

## 验证方式

1. `npm run build`
2. `git diff --check`
3. 浏览器访问 `/admin/meetings/1?tab=checkins` 检查首屏、弹窗、模式切换、控制台日志和截图。

## 完成记录

1. 已在首屏增加“工作人员端当前签到场次”摘要，展示默认场次、时间、已签到和待签到人数。
2. 已删除“允许手动调整默认场次”开关，将手动调整默认场次固定为三种签到模式的共同能力。
3. 已将场次列表默认状态收敛为左侧圆点表达，并改为外圈加内芯结构，避免圆点变形。
4. 已将新增/编辑签到场次从常驻表单改为弹窗，缩短签到管理主页面。
5. 已将日期场次生成按钮改为根据生成状态显示“生成日期场次”“补齐缺失日期场次”或“已生成 x/x 天”。
6. 已优化场次对比说明，明确当前场次、对比场次以及新增/减少名单的业务含义。
7. 已完成 `npm run build`、`git diff --check` 和浏览器渲染验收。本次仅修改前端，不需要重启后端。
