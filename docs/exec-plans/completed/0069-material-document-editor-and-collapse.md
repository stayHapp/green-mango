# 执行计划：会议资料文档编辑与折叠列表

## 任务名称

将会议资料正文升级为受限文档编辑，并在嘉宾端使用默认收起的折叠列表。

## 背景

会议资料现已支持多条正文和附件，但管理员只能使用普通文本框，项目符号、编号和重点内容无法稳定表达。嘉宾端默认展开全部正文，资料较长时会形成很长的移动端页面，难以先浏览标题再选择阅读。

## 用户确认状态

用户已明确同意调整，并确认：

- 会议资料正文使用文档编辑形式。
- 嘉宾端默认只显示资料标题，点击后展开详细内容。

## 目标

- 管理员可在资料正文中使用段落、加粗、项目符号、编号和缩进。
- 编辑器粘贴内容时移除样式、脚本、图片、链接等非白名单结构。
- 新版富文本编码后继续保存到现有 `content` 字段，不新增数据库迁移和 API。
- 历史普通文本自动转换为文档内容，不要求重新录入。
- 嘉宾端资料默认全部收起，点击标题独立展开或收起正文和附件。
- 桌面端与移动端均保持紧凑、清晰并满足键盘与读屏基础语义。

## 不在本次范围内的内容

- 不支持字体、字号、颜色、图片、表格、链接和任意 HTML。
- 不增加单选手风琴限制，允许嘉宾同时展开多份资料。
- 不修改资料附件、权限、排序和数据库结构。

## 技术决策与待确认项

- 使用 `material-rich:` 前缀和 URI 编码保存经过白名单清洗的 HTML。
- 白名单仅允许 `strong`、`br`、`div`、`p`、`blockquote`、`ul`、`ol`、`li`。
- 历史普通文本在编辑和展示时转换为安全段落。
- 嘉宾端使用原生按钮、`aria-expanded` 和关联内容区域实现折叠交互。

## 注释要求

所有新增函数和关键逻辑使用完整简体中文文档注释，富文本清洗、历史兼容和折叠状态必须说明安全或业务意图。

## 分步计划

1. 实现会议资料富文本清洗、编码、解码和普通文本兼容工具。
2. 实现受限文档编辑器并接入管理端资料表单和列表摘要。
3. 将嘉宾端改成默认收起、点击独立展开的资料列表。
4. 更新产品和架构文档。
5. 运行前端构建，并通过浏览器验证管理端编辑器和嘉宾端桌面、移动折叠交互。

## 验收标准

- 现有三份资料无需重新保存即可正常展示。
- 管理员打开历史正文时可以直接继续排版并保存。
- 新保存内容中的加粗、项目符号、编号、缩进和换行在嘉宾端一致呈现。
- 嘉宾初次进入只看到标题；点击一项只改变该项展开状态。
- 附件仅在所属资料展开后显示并可继续下载。

## 验证方式

- 运行 `npm run build`。
- 浏览器检查管理端编辑窗口工具栏、历史正文加载和表单状态。
- 浏览器检查嘉宾端默认收起、展开、再次收起和多项独立展开。
- 使用桌面和 390px 移动端视口检查布局与控制台。

## 风险与注意事项

- `document.execCommand` 仍被主流浏览器支持但属于兼容 API；当前用于 MVP 轻量编辑器，后续复杂编辑需求应采用正式编辑器内核。
- URI 编码会增加字符长度，正文仍受后端 20,000 字限制；界面需说明为轻量文档内容。
- 只在客户端展示经过白名单清洗的内容，绝不直接渲染原始字符串。
