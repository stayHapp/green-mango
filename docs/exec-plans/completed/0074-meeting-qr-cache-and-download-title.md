# 执行计划 0074：会议二维码缓存复用与下载标题排版

## 任务名称

管理员端会议入口二维码只生成一次：域名未变动时刷新页面直接复用之前二维码；下载图片中的标题完整呈现并居中。

## 背景

当前会议入口二维码由前端 `qrcode` 库在页面内生成，`meetingQrCode` 初始为空，刷新页面后需要管理员重新点击「生成二维码」。下载的 PNG 中会议标题使用单行 `fillText` 绘制，标题较长时文字溢出画布、显示不完整。经用户确认：

- 会议二维码只需生成一次；域名地址没有变动时，刷新页面应直接显示之前的二维码。
- 下载的二维码上方文字不能省略，需要全部呈现并居中对齐。

## 现状约束

- 后端未持久化会议公开链接与二维码，公开访问链接由前端按浏览器 origin 拼接生成。
- 二维码内容即会议入口 URL，同一 URL 生成的二维码图片内容一致，适合本地缓存复用。

## 执行前必须读取

- `AGENTS.md`
- `docs/architecture/frontend.md`

## 目标

- 首次进入已发布会议时自动生成入口二维码并写入本地缓存；再次刷新且域名（入口 URL）未变化时直接显示缓存二维码。
- 域名地址发生变化时缓存失效并自动重新生成。
- 下载的二维码图片中，会议标题自动换行、全部呈现、居中显示；二维码与日期信息随标题行数自适应下移，不超出画布。

## 不在本次范围内的内容

- 不新增后端字段与数据库迁移，不改动嘉宾端二维码逻辑。
- 不改变「重新生成二维码」按钮，域名变更或图片异常时仍可手动重新生成。

## 分步计划

1. 编写本执行计划。
2. 新增会议二维码本地缓存读写函数（以会议 ID 为键，保存入口 URL 与图片数据）。
3. 修改 `generateMeetingEntryQrCode`：生成成功后写入缓存；新增 `restoreOrGenerateMeetingEntryQrCode`：页面加载后优先复用同 URL 缓存，否则自动生成。
4. 修改下载绘制：标题按字符测量自动换行、全部呈现且每行居中，画布高度与二维码位置随标题行数自适应。

## 验收标准

- 已发布会议首次进入自动显示二维码；刷新页面后立即显示，无需再次点击生成。
- 修改域名地址后刷新，自动按新地址重新生成二维码。
- 下载的 PNG 中长标题完整呈现、逐行居中，二维码与日期不被截断。
- 未发布会议不生成二维码，行为与现状一致。

## 完成记录

实现完成，验证结果：

- 缓存复用：新增按会议 ID 区分的本地缓存（保存入口 URL 与二维码图片数据）；已发布会议首次进入自动生成二维码并缓存，刷新且入口 URL 未变化时直接复用，不再要求重复点击生成。

- 下载排版：标题按画布字体测量宽度自动换行、每行居中、全部呈现；画布高度与二维码、日期位置随标题行数自适应，不再溢出截断。
- 构建：`npm run build` 通过；未发布会议仍不生成二维码。
