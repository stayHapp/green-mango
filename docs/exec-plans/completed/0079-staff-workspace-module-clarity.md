# 执行计划 0079：工作人员端模块职责梳理

## 任务名称

按用户确认的方案整理工作人员端三个模块：手动签到仅展示未签到人员、同行登记仅支持已签到主嘉宾并可展开查看同行、签到记录增加可点击下钻的同行统计并理顺统计口径。

## 背景

同事反馈工作人员端四个功能模块混乱。经梳理，根源包括：手动签到列表混入已签到嘉宾、同行登记允许未签到主嘉宾登记（产生"同行已签、主嘉宾未签"的异常状态）、同行明细只能到签到记录查看、签到记录统计把同行嘉宾混入主嘉宾口径且数字不可点击。用户已确认三项优化方向，并选择同行登记中未签到主嘉宾「彻底不显示」。

## 用户确认状态

已确认。用户确认三项优化内容，并明确同行登记中未签到主嘉宾彻底不显示。

## 目标

- 手动签到列表仅显示未签到嘉宾，不提供已签到嘉宾的操作入口，也不展示提示条。
- 同行登记列表仅显示已签到主嘉宾；主嘉宾卡片可展开查看已登记同行（姓名、电话、备注、签到时间与方式）；登记成功后刷新并展开。
- 签到记录支持按姓名、手机号搜索；参会人员视图按已签到、未签到分组展示全部主嘉宾。
- 签到记录统计区改为可点击的四维口径：参会人员（主嘉宾）、同行人员、已签到、未签到；点击后列表过滤展示对应人群。
- 统计口径理顺：主嘉宾与同行嘉宾分开计数，不再混算；同行人员统计与下钻明细均按当前签到场次计算，保证数字与列表一致。

## 不在本次范围内的内容

- 不调整扫码签到的行为。
- 不修改后端接口与数据库；仅在前端重组现有数据。
- 不改动签到记录中主嘉宾展开同行的现有交互。

## 技术决策与待确认项

- 同行明细复用 `checkIns`（签到记录）按 `companionOfId` 归组，无需新增接口。
- 未签到主嘉宾数据仍存在于嘉宾列表，仅不在同行登记模块展示。
- 签到记录过滤状态为模块内状态，切换模块时重置为「全部」。

## 分步计划

1. 手动签到：过滤未签到嘉宾，命中已签到人员时展示提示。
2. 同行登记：仅展示已签到主嘉宾，增加同行展开子列表，登记成功后刷新并展开。
3. 签到记录：统计区改为四维可点击过滤，补充未签到与同行列表视图。
4. 样式：统计区四列布局与同行展开子列表样式。
5. 构建验证、更新文档与 CHANGELOG、归档执行计划。

## 验收标准

1. 前端构建通过，无类型错误。
2. 手动签到列表不出现已签到嘉宾。
3. 同行登记列表只有已签到主嘉宾；展开可查看同行明细，登记后自动展开。
4. 签到记录支持搜索，参会人员视图按已签到、未签到分组展示；四个统计数字可点击过滤，主嘉宾与同行统计口径正确，同行数字与明细一致。
