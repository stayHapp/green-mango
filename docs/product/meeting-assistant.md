# 会议服务

“会议服务”是面向参会者的产品名称；现有代码、接口和数据库中的 `meeting assistant`、`assistant-features` 继续作为内部技术名称。

## 功能范围

会议服务沿用嘉宾端已有五个固定入口：会议日程、会议资料、天气提醒、路线导航和联系会务。每项功能均由会议管理员维护，并按会议独立控制发布状态。

面向嘉宾的“会议资料”继续使用内部功能标识 `manual`。该兼容关系不要求修改现有数据库、API、路由和历史数据。嘉宾端完整信息架构和展示规范见 `guest-experience.md`。

## 发布与访问规则

- 管理员可以编辑功能正文和未发布提醒；会议日程在后台使用按日期、时段和环节拆分的结构化编辑器。
- 管理员可以为每项服务独立设置“公开可见”或“仅登录嘉宾可见”。
- 公开可见的服务允许未登录访问者从会议公开首页直接查看；仅登录嘉宾可见的服务会引导用户完成当前会议身份核验。
- 功能发布后，有访问权限的用户点击入口查看管理员编辑的正文。
- 功能未发布时，入口仍然保留；有访问权限的用户点击后查看管理员编辑的提醒。
- 嘉宾点击任一功能后进入独立详情页；五项详情页统一使用“左侧返回、黑色标题居中”的标题栏，正文区域不重复显示页面大标题。
- 会议日程使用日期分组和紧凑时间轴呈现，突出时间段、环节、内容和可选地点；天气提醒使用管理员确认地点的当前天气卡片和近期预报列表；路线导航展示导航按钮和到场说明。
- 未发布功能不得向任何访问者泄露草稿正文或联系人数据；公开可见只影响未发布提醒是否可查看。
- 会议日程后台采用结构化编辑并序列化回通用正文；会议资料使用独立条目和受限文档编辑；天气与路线继续使用通用正文。

## 前端阶段边界

会议助手配置已经完成服务端持久化。天气使用和风天气真实数据；路线位置通过高德地点搜索确认，两个功能共用会议导航坐标。

## MVP 产品边界结论

五项功能继续使用固定功能标识、未发布提醒和发布状态。会议资料使用独立资料条目，管理员不能新增、删除或调整一级入口类型，避免引入页面编排系统。

### 会议日程

- 管理员通过左侧日期导航和右侧时段、环节表单维护日程，可新增或删除日期、时段与环节，并可复制环节或调整时段顺序。
- 单个环节只编辑时间段、环节、内容和地点；时间段由开始时间和结束时间组成，内容支持换行、加粗、增加缩进和减少缩进。
- 内容仅允许加粗、段落、换行和缩进结构，编辑器失焦、保存编码和嘉宾端展示前都会执行白名单清洗，不支持字体颜色、图片、链接或任意 HTML。
- 保存时前端将富文本编码为单行 `rich:` 内容字段并序列化为现有正文，不修改数据库和 API；历史主题、嘉宾信息会合并到新版内容字段。
- 嘉宾端将正文转换为日期切换、时段分组和紧凑时间轴；新版条目使用 `环节｜rich:编码内容｜地点`，历史三字段和四字段正文继续兼容，无法识别的正文仍安全展示。
- 暂不建立日程日期、环节、讲者和分会场等结构化子表；需要服务端排序、冲突校验或多人协同独立编辑环节时再扩展。

### 会议资料

- 内部功能标识保持为 `manual`，产品界面不直接展示该技术标识。
- 管理员以资料列表维护多份内容，每份资料包含必填标题、可选正文和可选附件，正文和附件至少提供一项。
- 资料正文使用受限文档编辑器，支持段落、加粗、项目符号、编号、首行缩进 2 字符和整段缩进，并统一采用两端对齐；不支持字体、颜色、图片、表格、链接或任意 HTML。
- 嘉宾端默认只展示资料标题，点击后独立展开正文；有附件时在标题下提示，展开后显示原文件名、文件大小和下载操作。
- “会议手册”作为“会议资料”的子项，不新增或恢复一级固定入口。
- 当前支持附件下载，不提供在线预览、版本管理或结构化章节。

### 天气提醒

- 优先使用管理员确认的导航坐标查询天气；历史会议没有坐标时，按会议地址中的区县、城市和地点文本依次降级匹配。
- 管理员正文用于补充穿衣、雨具和出行提醒，不保存第三方天气响应快照。
- 天气由后端代理和风天气并缓存；管理员正文只补充穿衣、雨具和出行提醒。
- 会议日期超出天气服务可预报范围时必须明确提示，不能把近期天气描述为会议当天预报。

### 路线导航

- 管理员通过地点搜索选择准确会场，系统保存名称、地址和高德坐标。
- 嘉宾端只负责调起高德地图或 H5 导航，不在知会内部计算路线。
- 路线正文作为停车、入口、楼栋、楼层和签到台等到场说明。
- 地图应用无法调起时保留高德 H5 页面作为回退。
- 历史会议没有导航坐标时，继续展示会议地址和文本交通提示。

### 联系会务

- MVP 仅维护文本联系方式，可写联系人、电话、服务时段和紧急联系说明。
- 纯文本中的合法电话号码可以由终端提供基础拨号能力，但暂不建立结构化联系人列表、即时通讯或分级紧急联系人字段。

## 后端实现约束

- 每个会议固定且仅有 `agenda`、`manual`、`weather`、`route`、`contact` 五条配置。
- 管理员接口返回全部五项配置，并允许按功能标识修改正文、未发布提醒、发布状态和访问级别。
- 公开接口只返回 `access_level=public` 的服务；仅登录嘉宾可见的服务必须由后端拒绝，不能只靠前端隐藏。
- 嘉宾接口允许已登录嘉宾读取所属会议的五项服务，不受公开访问级别限制。
- 已发布功能返回正文；未发布功能只返回未发布提醒，服务端不得返回正文或联系人草稿。
- `manual` 已发布时通过独立资料接口返回条目；未发布时不得返回资料列表或附件。
- 历史和新增服务默认使用“仅登录嘉宾可见”，避免升级时意外公开既有内容。
- 天气数据不写入会议助手配置表，真实天气接口与配置接口保持分离。
- 通用功能正文与提醒继续使用纯文本。会议资料富文本在前端清洗后以 `material-rich:` 前缀和 URI 编码保存到现有正文列，展示前必须再次经过标签白名单清洗；后端仍按普通字符串设置长度限制，不直接接收或渲染原始 HTML。
